# 非公式イベント概要（サイト運用方針）

**更新日:** 2026-11-17  
**対象:** BLAZE CROWN 攻略サイト（`blaze-crown.com`）上で開催する、**非公式**のプレイヤー向けイベント  
**前提:** 実プレイは **公式アプリ** 内。サイトは参加登録・ミッション案内・達成申告・運営確認のみを担う。

---

## 目的

- 攻略サイトの読者・プレイヤーに、ミッション形式の遊び方を提供する
- アプリの対戦（例: 10 勝、特定キャラ編成、特定ユーザーとの対戦など）を **サイト上の進行表** と結びつける
- **公式との API 連携は行わない**。達成判定は **参加者の申告＋画像証拠** と **運営の目視確認** で行う

---

## 非公式であることの明示

- 当サイトおよびイベント主催者は **ブレイズクラウン公式・運営会社ではない**
- 賞品・ルール変更・不具合対応は **主催者の裁量** とし、ゲーム内のランキング賞や公式キャンペーンとは **別枠** であることを参加者に明示する
- ゲーム利用規約・βテスト注意（データ改変・不正行為の禁止等）を **順守** したプレイのみを対象とする

---

## 参加フロー（想定）

```text
1. イベントページを開く
2. Google アカウントでログイン（パスワードはサイト側では持たない）
3. 初回のみプロフィール入力（2 回目以降はスキップ）
4. ミッション一覧を読み、アプリでプレイ
5. 各ミッション完了後：「完了」申告 ＋ 証拠画像のアップロード
6. 運営が目視で確認し、承認 / 差し戻し
7. 全ミッション承認済みで「ミッション達成者」とみなし、抽選対象となる
8. （任意）ミッション達成後、対戦結果を追加申告して抽選の当選比重を上げる
```

---

## 認証・プロフィール

| 項目 | 方針 |
|------|------|
| ログイン | **Google のみ**（既存技術方針: Supabase Auth） |
| パスワード | **不要**（Google 側の認証に任せる） |
| メールアドレス | **フォームでは入力させない**。ログインアカウントに紐づくメールを内部利用（当選・問い合わせ等）。利用目的はプライバシーポリシーに記載 |
| 表示名（ユーザー名） | **初回必須**。サイト上の表示・運営確認用 |
| X（Twitter）アカウント | **任意**。`@` 表記を正規化して保存 |
| ゲーム内 ID / フレンドコード | **任意**（推奨: ミッションが複数・対戦指定がある場合は入力を促す）。自動連携はしない |

**識別の主体:** 参加者の一意性は Supabase の `user id` で管理する。表示名の重複は許容してよい。

## 今回の開催内容（ミッション・景品）

### ミッション一覧（全 3 つ）

| # | 種別 | 内容 | サイト側の扱い |
|---|------|------|----------------|
| 1 | **必須** | **累計 5 勝**（編成・モードはイベント規約どおり） | 5 勝到達が分かる証拠（戦績画面 or 該当する結果画面のスクショ） |
| 2 | キャラ指定（ランダム） | **β 開始時点の初期キャラ 10 体** のうち、参加者ごとにサイトが **ランダムで 1 体** を割り当て。そのキャラを **編成に含めて 2 勝** | 割り当てキャラ名を画面に表示。編成と勝利が分かるスクショ（2 勝分または戦績で確認可能なもの） |
| 3 | キャラ指定（ランダム） | ミッション 2 と **別のキャラ** を同様にランダム割り当て。**編成に含めて 2 勝** | 同上 |

- ミッション 2 と 3 では **同じキャラが重複しない** よう、参加者ごとに **2 体を別々に抽選** する（実装時: 10 体から重複なしで 2 体）。
- **1 試合は、条件を満たすミッションに同時に反映してよい**（例: 割当キャラを入れた勝利 1 回が、累計 5 勝の「1 勝」にも、該当キャラ「2 勝」ミッションの「1 勝」にもカウントされる）。
- 証拠画像はミッションごとに申告してよい。**同一のスクショを複数ミッションの証拠に使ってもよい**（その試合が各ミッションの条件を満たしている場合）。
- **3 つすべて運営承認済み** の参加者のみ **ミッション達成者** とし、PayPay 抽選の対象とする。

### 景品

- **PayPay 1,500 円** を、ミッション達成者の中から **ランダム抽選で 2 名** に付与する。
- 抽選・送金手順・期限内の連絡方法は公開ページに記載する。

### ミッション達成後の「対戦結果」追加申告（当選比重アップ）

ミッション 3 つすべて承認されたあと、**任意**で対戦結果を追加送信できる。

| 項目 | 内容 |
|------|------|
| 対象となる対戦 | **勝ち・負け・引き分け** のいずれも可（イベント規約で対象モードを限定してよい） |
| 送信単位 | **1 試合（1 枚の証拠画像）＝ 1 回** |
| 当選比重（重み） | ミッション全達成時点の重みを **1** とする。その後、**運営承認された対戦結果 1 枚ごとに +0.01** |
| 式（参加者 \(i\)） | \(w_i = 1 + 0.01 \times n_i\)（\(n_i\) = 追加対戦結果の承認済み枚数） |
| 抽選 | ミッション達成者集合の上で、重み \(w_i\) に比例して **2 名を重複なし** で抽出 |
| 再利用 | **一度承認（または受理）に使った対戦結果画像は、二度と使えない**（同一画像ハッシュ・同一試合の再申告は却下）。ミッション証拠に使った試合・画像を、**加重用の追加対戦結果として再提出することも不可** |

参加者向け表現の例:「全ミッション達成で抽選に参加できます。達成後に対戦結果を送るたび、当選の重みが **0.01 ずつ** 増えます。」

### スクショ・承認の目安（今回）

- プレイヤー名・日付が読めること
- キャラ指定ミッション: **割り当てキャラが編成 3 体のいずれかに含まれる** ことが分かること
- 累計 5 勝: イベント開始後の勝利であることが運営が判断できること（規約で開始日時を明記）

## ミッション（今後の開催用・例）

開催ごとに上記「今回の開催内容」を差し替える。以下は別イベントの例。

| 例 | アプリ側の行為 | サイト側の確認 |
|----|----------------|----------------|
| 累計 N 勝 | ランクマ等で勝利 | 戦績・結果のスクショ |
| 特定キャラを編成して複数勝 | デッキ編成して対戦 | 編成と結果が分かるスクショ |
| 特定ユーザーと対戦 | フレンドバトル等 | 対戦結果スクショ |

**自動判定は行わない**（公式 API がないため）。ルールページに「何が写っていれば承認しやすいか」を事前に書く。

## 達成申告・証拠画像

- 各ミッションごとに **完了ボタン（申告）** と **画像アップロード**（1 枚以上、上限・形式は実装時に決定）
- ミッション達成後は **追加対戦結果** 用の申告種別を分ける（ミッション用と混同しない）
- 申告後のステータス例: `pending`（審査待ち）→ `approved`（承認）/ `rejected`（差し戻し・理由を表示）
- 差し戻し時は **再アップロード** を許可する（**同一試合の二重利用** は不可）
- 画像の **コンテンツハッシュまたは perceptual hash** を保存し、再利用を弾く（実装時）
- ボット対策: 既存方針どおり **Turnstile** を申告 API に載せることを検討

## 画面構成（必須）

イベントを回すために **プレイヤー向けページ** と **運営向けページ** の 2 系統が必要。静的公開（Astro）＋ React 島＋ Pages Functions と Supabase で実装する想定。

### URL（案）

| 種別 | パス | 備考 |
|------|------|------|
| 公開ランディング | `/games/blaze-crown/events/[eventSlug]/` | ルール・期間・非公式注意。未ログインでも閲覧可 |
| プレイヤーページ | `/games/blaze-crown/events/[eventSlug]/play/` | ログイン必須 |
| 運営ページ | `/games/blaze-crown/events/[eventSlug]/admin/` | 運営者のみ（下記） |

`eventSlug` は開催ごとに 1 つ（例: `cbt-paypay-2026-11`）。

### プレイヤーページ（`/play/`）

**誰が使うか:** Google ログイン済みの参加者。

| 機能 | 内容 |
|------|------|
| ログイン | Google（未ログイン時はランディングへリダイレクト or モーダル） |
| 初回プロフィール | 表示名（必須）、X（任意）、ゲーム内 ID（任意）。保存後は編集可（方針は開催前に決定） |
| ミッション状態 | 3 ミッションの説明・**割当キャラ名**（2・3）・申告ステータス（未提出 / 審査中 / 承認 / 差し戻し） |
| 証拠の提出 | ミッション種別を選び、画像アップロード＋完了申告（Turnstile） |
| 差し戻し表示 | 運営が入力した **却下理由** を表示し、再提出できる |
| 全ミッション達成後 | **追加対戦結果** の提出 UI（勝敗問わず）。現在の **抽選重み**（\(1 + 0.01 \times n\)）を表示 |
| 自分の提出履歴 | サムネイル・日時・種別・ステータス一覧（画像は本人のみ閲覧） |

プレイヤーページに **他参加者のプロフィールや画像は出さない**。

### 運営ページ（`/admin/`）

**誰が使うか:** サイト運営者のみ。

| 機能 | 内容 |
|------|------|
| アクセス制御 | Google ログイン ＋ **運営者許可リスト**（環境変数 `EVENT_ADMIN_EMAILS` 等、カンマ区切り）で Pages Function 側でも検証。**許可外は 403** |
| **登録ユーザー一覧** | イベント参加者全員の表: 表示名、登録日時、メール（運営のみ表示）、X、ゲーム内 ID、ミッション 1〜3 の状態、追加対戦結果の承認枚数、**現在の抽選重み**、全ミッション達成フラグ |
| 一覧の操作 | 表示名で検索・「審査待ちあり」でフィルタ・提出日時でソート |
| **画像の承認** | 審査キュー: `pending` の提出を新しい順に表示。各項目に **画像拡大**・種別（ミッション 1〜3 / 追加対戦）・申告者情報・提出日時 |
| 承認操作 | **承認** / **差し戻し**（理由テキスト必須）。承認時に画像ハッシュを確定し、二重利用チェックに使う |
| 抽選補助（任意・初期は手動でも可） | ミッション達成者のみを重み付きでエクスポート（CSV）し、抽選はスプレッドシート等でも可。将来は「抽選実行」ボタンを同ページに追加 |

運営ページは **noindex**（`robots` / meta）とし、ナビゲーションにも載せない。URL は関係者のみ配布。

### API（Pages Functions 案）

| メソッド | パス | 用途 |
|----------|------|------|
| GET | `/api/events/[slug]/me` | 自分のプロフィール・ミッション状態・重み |
| POST | `/api/events/[slug]/profile` | 初回・更新プロフィール |
| POST | `/api/events/[slug]/submissions` | 画像メタ＋アップロード用 signed URL または multipart |
| GET | `/api/events/[slug]/submissions` | 本人の提出一覧 |
| GET | `/api/events/[slug]/admin/participants` | 登録ユーザー一覧（運営のみ） |
| GET | `/api/events/[slug]/admin/submissions?status=pending` | 審査キュー |
| PATCH | `/api/events/[slug]/admin/submissions/[id]` | 承認 / 差し戻し |

書き込み・運営 API は **service role** 経由。クライアントに service role を載せない（[TECH_STACK.md](./TECH_STACK.md) と同じ）。

### データ（Supabase 案・概要）

| テーブル | 主な用途 |
|----------|----------|
| `event_profiles` | `user_id` + `event_slug`、表示名、X、ゲーム内 ID、割当キャラ 2 体、作成日時 |
| `event_submissions` | 種別、画像 Storage パス、`status`、`rejection_reason`、`content_hash`、監査用 `reviewed_by` |

Storage バケットは非公開とし、画像 URL は **署名付き** または運営・本人のみ取得できる API 経由。

### フロント実装の置き場（案）

```text
src/pages/games/[game]/events/[slug]/index.astro    # ランディング
src/pages/games/[game]/events/[slug]/play.astro    # プレイヤー
src/pages/games/[game]/events/[slug]/admin.astro # 運営
src/components/events/                             # EventPlayDashboard, EventAdminPanel 等
functions/api/events/                              # 上記 API
supabase/migrations/*_event.sql
```

## 運営者の目視確認

運営者は **運営ページ** の審査キューと登録ユーザー一覧を使い、以下を確認する。

1. 申告ミッション種別とルールの一致
2. スクショに **登録表示名・ゲーム内名（ルールで指定した項目）** が含まれるか
3. 日付・勝利数・編成・対戦相手など、ミッションごとの必須要素
4. 明らかな加工・別プレイヤーの画像・同一画像の使い回し（疑いがあれば差し戻し）

承認は **人間判断** とし、疑わしい場合は参加者に X またはメールで追加確認してよい（連絡手段はイベント規約に記載）。

## スコープ外（初期）

- ゲームサーバーとの連携による勝敗・編成の自動取得
- メール＋パスワードによる独自会員登録
- ゲーム内ランキングとの公式連動
- 運営ページでの **抽選ボタン自動実行**（初回は CSV 手動抽選でも可）
- 景品は開催ごとに決定（今回: PayPay 1,500 円 × 2 名）。金銭授与時は表示・税・青少年向け配慮を公開ページに記載
